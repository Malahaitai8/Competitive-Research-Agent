# 三项优化实施计划：进度展示、重跑实验、语义闭环

## 目标

本轮优化把竞品研究链路调整为“生成前材料门控 + 生成后语义校验 + 受控补救重跑”。

生成前的规则检查只负责 Evidence Gate，判断写报告前的材料是否足够；生成后的 Semantic Validator 才判断最终报告和竞品矩阵是否被证据支撑。语义校验发现问题后，不开放自由工具调用，只交给 Remediation Controller 做白名单补救。

## 运行链路

```text
检索/抓取
-> Evidence Gate 材料门控
-> 必要时材料补救
-> Writer 生成报告草稿
-> 生成竞品矩阵
-> Semantic Validator 语义校验
-> Remediation Controller 选择补救动作
-> 局部重写 / 补搜后重写 / 风险标注
-> 复检受影响项
-> 最终报告与 analysis JSON
```

## 关键设计

- Evidence Gate 不判断最终报告语义，只检查竞品证据、维度证据、官方来源、时间信息和关键事实缺口。
- Semantic Validator 是一个 LLM 节点，内部同时检查 `matrix_validation` 和 `claim_validation`，不拆成两个模型节点。
- 语义状态统一为 `supported / weakly_supported / unsupported / needs_human_review`。
- 补救动作只允许 `rewrite_only / search_and_rewrite / risk_only`。
- 后端实际工具链仍然受控：`repair_search -> web_search -> scrape_url -> extract_evidence -> local_rewrite -> semantic_validate`。
- 默认最多 1 个 remediation cycle；2-cycle 只作为实验对照或深度模式候选。

## 进度展示优化

- 后端统一进度 metadata：`stage / status / severity / message_zh / raw_message / normalized_at`。
- 前端增加兜底归一化，把常见英文日志映射为中文。
- warning/error 与普通日志分层展示，避免任务异常混在普通进度里。
- 保留 raw message 方便调试。

## 重跑实验方案

实验对象不是“补搜轮次”，而是完整 remediation cycle。

一个 cycle 包含：

```text
诊断 semantic gaps
-> 判断 rewrite_only / search_and_rewrite / risk_only
-> 必要补搜
-> 局部重写
-> 复检
```

对同一批 case 比较：

- `0-cycle`：只生成报告和风险，不补救。
- `1-cycle`：最多一次补救重跑。
- `2-cycle`：第一次补救后仍 unsupported，再允许一次补救。
- `pre-only`：只在 Evidence Gate 后补救，生成后只标风险。
- `post-only`：生成前只诊断，生成后基于语义校验补救。

记录指标：

- unsupported 修复率；
- weakly_supported 降低率；
- 语义 gap 修复率；
- 正文 claim 支撑率；
- 重写章节数；
- 新增来源数；
- 搜索/抓取次数；
- LLM 调用次数；
- 总耗时；
- 重复来源数；
- 新错误数；
- 待人工确认项数量。

生产默认根据实验数据选择。初始默认是 `1-cycle`，优先 `rewrite_only`，证据不足才 `search_and_rewrite`。
