# 浏览器刷新后调研任务恢复设计

## 目标

当竞品调研正在执行时，浏览器刷新或关闭标签页不应终止后端研究。用户重新打开页面后，应恢复同一任务的当前阶段、历史日志和运行状态；任务完成后正常进入报告结果页。

本设计仅覆盖浏览器连接中断。后端进程重启后不保证继续执行未完成任务。

## 当前问题

- 前端使用页面内存中的 `activeResearchTask` 保存进行中任务，并生成临时 `running-*` ID。刷新后这些状态丢失。
- 后端研究协程与单个 WebSocket 生命周期绑定。连接断开时 `finally` 会取消 `running_task`，导致研究本身中止。
- 仅把前端状态写入 `localStorage` 会恢复一个可能已经停止的假任务，无法满足要求。

## 方案

### 后端任务注册表

新增进程内任务注册表，以真实 `task_id` 为键保存：

- 任务请求与展示标题
- `queued`、`running`、`complete`、`failed` 状态
- 当前研究阶段
- 可重放的 WebSocket 事件
- 后台 `asyncio.Task`
- 当前订阅连接
- 完成后的报告路径与竞品分析数据
- 失败原因和更新时间

研究协程由注册表创建并持有，不属于某个 WebSocket。WebSocket 断开只移除订阅者，不取消后台任务。

### WebSocket 协议

启动请求仍使用现有 `start` 命令及研究字段，后端在真正执行前发送：

```json
{
  "type": "task_accepted",
  "task_id": "task_<timestamp>_<hash>",
  "status": "running"
}
```

页面恢复时发送：

```text
subscribe {"task_id":"task_<timestamp>_<hash>"}
```

后端依次发送任务快照、已有事件，再把新连接加入实时订阅。若任务已完成，快照中包含现有报告文件地址；若失败，包含可展示的失败原因。

未知或已清理的任务返回 `task_not_found`，前端移除失效的本地恢复记录并回到欢迎页。

### 事件分发

现有研究日志、阶段事件、报告内容和文件路径继续使用原消息结构。新增一个能够同时：

1. 将事件写入任务缓冲区；
2. 向当前订阅者广播；
3. 在订阅者暂时为空时继续接收研究输出；

的任务日志通道，避免复制研究流程或修改研究、下载和报告接口。

事件缓冲设置合理上限，保留完整阶段事件和最近日志；最终任务快照始终保存报告路径和终态。

### 前端恢复

- 收到 `task_accepted` 后，用真实 `task_id` 替换临时 ID。
- 将任务 ID 和最小展示信息写入版本化 `localStorage`，并同步 URL hash。
- 页面初始化时，若 URL 或本地记录指向进行中任务，则先显示恢复态并建立 WebSocket。
- WebSocket 打开后发送 `subscribe`，不重复发送 `start`。
- 收到快照与重放事件后，恢复四阶段进度、详细日志和历史条目。
- 收到完成文件路径后，沿用现有报告加载逻辑进入结果页，并清除进行中恢复记录。
- 收到失败或任务不存在后，分别进入失败页或欢迎页。

## 生命周期

```text
开始调研
  → 后端创建 task_id 和后台协程
  → 前端保存 task_id
  → 正常接收事件

浏览器刷新
  → 旧 WebSocket 断开
  → 后端只取消订阅，研究继续
  → 新页面读取 task_id
  → subscribe(task_id)
  → 后端重放快照与日志
  → 继续实时推送
  → 完成后进入报告
```

## 错误处理

- 后端任务失败：保存错误终态和已产生的日志，重连后仍可查看。
- 网络短暂断开：前端继续使用现有重连机制，但优先重新订阅，不重新启动任务。
- 无效任务 ID：清理 URL 与本地恢复记录，显示轻量提示并回到欢迎页。
- 后端重启：进程内注册表清空，按无效任务处理；本轮不实现断点续跑。
- 多个页面订阅同一任务：允许同时只读接收同一事件，不重复启动研究。

## 测试

### 后端

- 启动命令立即返回真实任务 ID。
- WebSocket 断开不会取消注册表中的研究协程。
- 重连订阅能够收到状态快照和历史事件。
- 订阅完成任务会收到报告文件路径。
- 订阅失败任务会收到失败原因。
- 订阅未知任务返回 `task_not_found`。
- 同一任务不会因重复订阅而重复执行。

### 前端

- `task_accepted` 后 URL、历史条目和本地恢复记录使用真实 ID。
- 页面初始化能够从 URL 或本地记录恢复。
- 恢复连接只发送 `subscribe`，不发送新的 `start`。
- 重放事件能够恢复四阶段和详细日志。
- 完成、失败、无效任务分别进入正确视图。

### 端到端

启动一次当前竞品调研，在运行中刷新页面，确认：

1. 后台进程不中止；
2. 页面恢复原任务阶段和日志；
3. 实体归一、搜索、生成前门控、固定报告结构、生成后语义校验和受控补救事件按当前配置执行；
4. 完成后自动进入报告；
5. 生成 `_competitive_analysis.json`，并包含阅读前说明所需数据。
