# AI 产品竞品研究 Agent

本项目基于 GPT Researcher 改造，目标是把通用深度研究能力产品化为面向 AI 产品经理的竞品研究 Agent。

## 项目定位

传统 AI 产品竞品调研存在信息分散、时效性难保证、对比口径不一致、引用难以支撑结论等问题。本项目保留 GPT Researcher 的搜索、抓取、并发研究、上下文聚合、引用追踪和报告导出能力，在输入、Prompt、报告结构和后处理层做轻量改造。

## 当前改造范围

已完成：

- 结构化竞品研究输入：
  - 研究主题；
  - 竞品名称；
  - 研究维度；
  - 地区；
  - 时间范围；
  - 补充要求。
- 前端基础校验：
  - 竞品数量限制为 2 到 4 个；
  - 研究维度限制为 1 到 6 个。
- 标准研究任务拼接：
  - 将结构化字段转换为带 `[COMPETITIVE_RESEARCH_MODE]` 标记的研究任务。
- 竞品研究 Planner Prompt：
  - 要求覆盖全部竞品；
  - 要求围绕统一维度拆解；
  - 要求优先生成可公开验证的问题；
  - 要求考虑地区和时间范围。
- 竞品报告 Prompt：
  - 固定输出产品经理可读的 10 个章节；
  - 区分事实、分析和建议；
  - 关键事实要求附来源；
  - 缺失信息标记为“暂未找到公开信息”；
  - 来源冲突需要说明。
- 轻量后处理：
  - 检查必需章节；
  - 统计引用 URL；
  - 用 URL/domain 关键词粗略统计官方倾向来源；
  - 保存 JSON 分析结果。
- 评测任务种子：
  - `evals/competitive_research_tasks.json` 中包含 10 个竞品研究任务。

未完成：

- 真实 API Key 下的端到端研究任务；
- 基于真实报告的竞品矩阵后处理；
- 真实 Badcase 记录；
- 评测指标真实数据；
- 最终简历数据。

## 核心链路

```text
结构化输入
→ 前端校验
→ 标准竞品研究任务
→ Planner 生成子问题
→ 并行搜索与抓取
→ 相关内容压缩
→ 上下文聚合
→ 竞品报告生成
→ 章节/来源后处理
→ 前端展示与导出
```

## 运行方式

安装依赖后启动服务：

```bash
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

访问：

```text
http://127.0.0.1:8000/
```

真实研究任务需要至少配置：

```text
OPENAI_API_KEY=
TAVILY_API_KEY=
```

可选配置：

```text
RETRIEVER=tavily
LANGUAGE=chinese
SMART_LLM=openai:<model>
STRATEGIC_LLM=openai:<model>
FAST_LLM=openai:<model>
```

## 后处理输出

竞品研究任务完成后，会额外生成：

```text
outputs/<task>_competitive_analysis.json
```

该文件包含：

- 原始结构化请求；
- 必需章节清单；
- 已出现章节；
- 缺失章节；
- 章节完整率；
- 引用 URL 数量；
- 官方倾向 URL 数量；
- 官方倾向来源占比。

注意：官方倾向来源统计是基于 URL/domain 关键词的启发式结果，只能作为排查线索，不能直接当作最终可信度指标。

## 面试表述边界

可以如实表述：

- 复用了 GPT Researcher 的深度研究底座；
- 复用了搜索、抓取、并发、上下文聚合、引用追踪和导出能力；
- 个人改造集中在竞品研究场景定义、结构化输入、Prompt 约束、报告结构、后处理和评测设计。

不能表述为：

- 从零实现了搜索引擎；
- 从零实现了网页爬虫；
- 从零实现了完整深度研究 Agent；
- 已经取得未真实验证的评测指标。

## 评测计划

使用 `evals/competitive_research_tasks.json` 作为评测种子，后续记录：

- 维度覆盖率；
- 关键事实准确率；
- 官方来源占比；
- 引用匹配率；
- 报告结构完整性；
- 时效合格率；
- 单次任务耗时；
- 单次任务成本；
- Badcase 和修复前后对比。

所有指标必须来自真实运行和人工抽样检查。
